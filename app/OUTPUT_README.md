# Результат распознавания

## Главный файл — `chunks.jsonl`

Это то, что передаётся на следующий этап (векторизация и поиск с LLM).
Весь распознанный текст разбит на фрагменты по ~1200 символов; одна строка файла = один фрагмент:

```json
{"chunk_id": "a1b2c3d4e5f60718:12", "doc_id": "a1b2c3d4e5f60718",
 "source_path": "СТО/СТО 7.2-2025.pdf", "title": "СТО 7.2-2025",
 "pages": [3, 4], "text": "4.1 Извещение об изменении согласовывают ...",
 "lines": [[3, 18], [4, 5]], "boxes": {"3": [[56.0, 610.2, 540.1, 622.0]]},
 "has_table": false, "ocr": true}
```

| Поле | Что это |
|---|---|
| `text` | текст фрагмента (ручные исправления слов уже подставлены) |
| `source_path` | путь к исходному файлу в общей папке — по нему назначаются права доступа |
| `pages` | страницы, откуда взят фрагмент |
| `boxes` | координаты строк на странице (для подсветки фрагмента при показе источника) |
| `doc_id` | ссылка на полный текст документа в `documents/<doc_id>.json` |

Таблицы (Excel, Word) записаны строками `| ячейка | ячейка |`, шапка таблицы повторяется в каждом фрагменте.

## Вспомогательное

* `documents/<doc_id>.json` — полный текст каждого документа по страницам и строкам (нужен, чтобы показать пользователю источник).
* `report.xlsx` — отчёт: все файлы и их статус, ошибки, слова, отправленные на проверку.

Векторы здесь не считаются: это делается на следующем этапе из `chunks.jsonl`
(модель эмбеддингов может меняться, а распознавание повторять не придётся).
