# olya_ocr — распознавание документов для LLM

Веб-сервис в Docker: загружаете файлы и папки → он распознаёт текст (включая сканы) →
на выходе один файл **`chunks.jsonl`**, готовый для следующего этапа (векторизация, поиск, ответы LLM).
Работает **без интернета**.

**Установка на Astra Linux:** [deploy/ИНСТРУКЦИЯ_Astra_Linux.md](deploy/ИНСТРУКЦИЯ_Astra_Linux.md).
Готовый комплект для флешки (образ + скрипты + инструкция) — в разделе **Releases** этого репозитория.

## Что умеет

* **Форматы:** PDF с текстом и PDF-сканы (решение «текст или распознавание» — для каждой страницы),
  Word (.docx, .doc, .rtf, .odt — включая вставленные в документ сканы), Excel (.xlsx, .xls, .csv),
  картинки (.tif многостраничный, .jpg, .png), .txt.
* **Распознавание:** Tesseract (русский + английский). Повёрнутые страницы выравниваются, плохие страницы
  повторно распознаются точной моделью, мусор (печати, подписи, рисунки) не попадает в текст.
* **Надёжность:** ошибка в файле не останавливает работу; каждая страница сразу сохраняется на диск, поэтому
  после сбоя или выключения компьютера распознавание продолжается с того же места; сервис сам запускается
  после перезагрузки.
* **Ошибки — сразу на странице** (повреждён, пароль, пустой, плохой скан, неподдерживаемый формат)
  и в отчёте `report.xlsx`.
* **Проверка слов:** слова, в которых система не уверена и которых нет в словаре, показываются с картинкой
  из скана — можно вписать правильное, оно попадёт в результат.

## Результат

Папка `output` (на Astra — `/opt/olya_ocr/output`):

| Файл | |
|---|---|
| **`chunks.jsonl`** | **результат для следующего этапа**: текст, разбитый на фрагменты ~1200 символов; у каждого — исходный файл (путь в общей папке), страницы, координаты строк |
| `documents/<id>.json` | полный текст каждого документа по страницам — чтобы показать пользователю источник |
| `report.xlsx` | отчёт: все файлы и статусы, ошибки, проверенные слова |

Формат фрагмента описан в [app/OUTPUT_README.md](app/OUTPUT_README.md) (этот же файл кладётся в `output/README.md`).

Почему не сразу векторы: они зависят от модели эмбеддингов, которую выберут и, возможно, будут менять на
следующем этапе. Распознавание — часы, векторизация готового `chunks.jsonl` — минуты.

## Для разработчика

```bash
docker compose up -d --build          # локальный запуск: http://localhost:8080
./scripts/export_image.sh             # комплект для флешки: dist/olya_ocr/
python scripts/make_test_set.py <папка_с_pdf> test_input   # тестовый набор с «плохими» файлами
python scripts/upload_folder.py test_input http://localhost:8080
```

Устройство: `app/main.py` — веб-сервер и API; `app/worker.py` — очередь и процессы-обработчики
(падение на одном файле не роняет сервис); `app/extract.py` — форматы; `app/ocr.py` — распознавание и поиск
сомнительных слов; `app/export.py` — сборка `chunks.jsonl` и отчёта; состояние — SQLite в томе Docker.

Настройки (переменные окружения): `WORKERS` (процессов, по умолчанию ядра−1), `OCR_MODE` (`fast`/`auto`/`best`),
`OCR_DPI` (300), `WORD_CONF` (55 — порог для слов на проверку), `CHUNK_CHARS` (1200).

Скорость на 6 ядрах: ориентировочно 60–150 страниц сканов в минуту; 3 ГБ сканов — 2–8 часов.
